# Third Coast Player Stats

A free, static companion site for Third Coast Volleyball players: power
rankings, team pages, a matchup predictor, player dynasty cards, and
playoff odds — all computed client-side from data a GitHub Actions
workflow archives from LeagueApps every 12 hours.

## Layout

- `/docs` — **everything GitHub Pages publishes**, and nothing else:
  - `/docs/*.html` — the pages (no build step, no framework).
    `index.html` is a thin **router**, not a screen. It first checks the
    saved team's program against `data/programs-index.json` (every
    LIVE/UPCOMING program) and, if that season has ended, forwards to
    `season.html`, which rolls the player into the new season. Otherwise
    it reads `data/schedule/{programId}.json` and forwards to
    `gamenight.html` (the next-game feed), `playoffs.html` (a deliberate
    stub — there is no live playoff data pipeline) or `search.html`.

    **Season rollover.** A saved team is `{programId, teamId}`, and
    LeagueApps starts a brand-new program, with brand-new team ids, for
    every season — so that pointer goes dead every few months.
    `season.html` finds the successor team by voting the old roster's
    players into whatever active team they appear on now (the
    `appearances` list in `data/people/{userId}.json` spans programs by
    design), and asks the player to confirm rather than switching
    silently, because a partial roster carry-over is genuinely ambiguous.
    It resolves against `programs-index.json` rather than
    `active-teams-index.json` on purpose: that index is built from parsed
    standings rows, so a season LeagueApps has announced but not yet
    posted standings for is invisible in it for weeks.
  - `/docs/assets` — shared CSS, JS and the SVG icon sprite.
  - `/docs/data` — the committed JSON the pages read. Regenerated by the
    archiver; never hand-edited.

    **The court map.** `court.html` shows the venue floor for one night,
    one slot at a time, in the broadcast board's own arrangement (north
    bank 8-12, centre 6-7, south bank 1-5). It is VENUE-wide, not
    team-wide: a real Tuesday is five leagues sharing twelve courts. That
    axis is wrong everywhere else in `docs/data`, where schedules are
    stored per program, so the archiver re-indexes them by night into
    `data/courts/{YYYY-MM-DD}.json` plus a small `courts/index.json`.
    One night is ~17KB and is all the screen ever needs; doing the merge
    in the browser instead would mean fetching every active program's
    schedule to draw one floor.
    **History across seasons.** Rosters are archived for *finished*
    seasons too, not just active ones — each one fetched once and read
    back from `data/rosters/` forever after, since a finished roster never
    changes. The first pass over the back catalog is ~4,000 pages, so a
    scheduled run spends at most 600 of them (`HISTORY_ROSTER_BUDGET`); a
    by-hand run can lift that with `ARCHIVE_HISTORY_BUDGET=10000`.
    LeagueApps only still serves rosters from mid-2022 on; earlier seasons
    have standings but empty rosters.

    From those rosters `archive/lineage.js` links every team to the team
    it was last season — by who is on it, not by name, since names change
    — and writes `data/lineage/{programId}.json`: each team's season
    count, its full season-by-season history, and `move: up | down` when
    last season was a different level of the same format. The ladder is
    AA > A > BB > B > Upper Rec (BB above B, per LeagueApps' own
    "(formerly Intermediate #1)" renames). Pop-ups, KOB/QOB and snake
    drafts are not rungs and never count as a previous season.

    **Omnisearch.** Every top bar has a magnifier that searches every
    player (first name) and team across every season, from one lazily
    fetched `data/search-index.json`.
    **Install guide.** A phone visitor in a plain browser (not the
    home-screen app) gets a full-screen "add to Home Screen" guide on every
    visit; "Not now" quiets it for that visit (a sliding 30 minutes).
    Android Chrome gets a real one-tap Install button. iOS gets animated
    steps and an arrow at Safari's own Share button, because no web page
    can open "Add to Home Screen" for the user. Desktop never sees it, and
    neither does the Puppeteer suite (`navigator.webdriver`) unless a test
    forces a platform with `window.__installNag`.
  - `/docs/tests` — the local Puppeteer UI suite and its fixture data.
  - `/docs/.nojekyll` — tells Pages to serve these files as-is instead of
    running them through Jekyll.
- `/archive` — the archiver (`node archive/fetch.js`), run by
  `.github/workflows/archive.yml`. **Deliberately outside `/docs`**:
  `archive/fixtures/` holds real captured LeagueApps pages (real names,
  kept for parser tests per the spec's test-fixture carve-out), and
  keeping them out of `/docs` means they can never be served as live web
  pages.

## Deploying to GitHub Pages

1. Push this repo to GitHub.
2. Settings → Pages → **Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: the default branch, folder: **`/docs`**
3. Save. The site is served at `https://<user>.github.io/<repo>/`.

No workflow, build step, or action is needed to publish — Pages serves
`/docs` directly. The only workflow in this repo is the archiver, which
just commits refreshed JSON into `docs/data/`; each such commit
re-publishes the site automatically.

Because `/docs` is the published root, page code fetches its data with
plain relative paths (`data/standings/1234.json`), which resolve
identically in local development and on Pages.

## Running it locally

```bash
node archive/_serve-repo-root.js   # serves docs/ at http://localhost:8124/
```

That serves exactly what Pages serves — `docs/` at `/`, and nothing above it.

## Tests

```bash
npm test                 # archiver unit tests (node --test archive/)
node docs/tests/run.js   # Puppeteer UI suite over every page
```

`npm test` runs the archiver's `node:test` suites against recorded
fixtures — it never touches the network. The UI suite is **dev-time
only** (not run in CI): it serves `docs/` with `docs/tests/fixtures/data`
substituted for the real `docs/data/`, then drives the pages with
`puppeteer-core`. It needs a local Chrome — the path is set at the top of
`docs/tests/run.js`.

## Running the archiver by hand

```bash
node archive/fetch.js    # hits live LeagueApps, writes docs/data/
```
