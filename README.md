# Third Coast Player Stats

A free, static companion site for Third Coast Volleyball players: power
rankings, team pages, a matchup predictor, player dynasty cards, and
playoff odds — all computed client-side from data a GitHub Actions
workflow archives from LeagueApps every 12 hours.

## Layout

- `/docs` — **everything GitHub Pages publishes**, and nothing else:
  - `/docs/*.html` — the pages (no build step, no framework).
    `index.html` is a thin **router**, not a screen: it reads the saved
    team's `data/schedule/{programId}.json` and forwards to
    `gamenight.html` (the next-game feed), `playoffs.html` (a deliberate
    stub — there is no live playoff data pipeline) or `search.html`.
  - `/docs/assets` — shared CSS, JS and the SVG icon sprite.
  - `/docs/data` — the committed JSON the pages read. Regenerated by the
    archiver; never hand-edited.
  - `/docs/tests` — the local Puppeteer UI suite and its fixture data.
  - `/docs/.nojekyll` — tells Pages to serve these files as-is instead of
    running them through Jekyll.
- `/archive` — the archiver (`node archive/fetch.js`), run by
  `.github/workflows/archive.yml`. **Deliberately outside `/docs`**:
  `archive/fixtures/` holds real captured LeagueApps pages (real names,
  kept for parser tests per the spec's test-fixture carve-out), and
  keeping them out of `/docs` means they can never be served as live web
  pages.

## Deploying to GitHub Pages

1. Push this repo to GitHub.
2. Settings → Pages → **Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: the default branch, folder: **`/docs`**
3. Save. The site is served at `https://<user>.github.io/<repo>/`.

No workflow, build step, or action is needed to publish — Pages serves
`/docs` directly. The only workflow in this repo is the archiver, which
just commits refreshed JSON into `docs/data/`; each such commit
re-publishes the site automatically.

Because `/docs` is the published root, page code fetches its data with
plain relative paths (`data/standings/1234.json`), which resolve
identically in local development and on Pages.

## Running it locally

```bash
node archive/_serve-repo-root.js   # serves docs/ at http://localhost:8124/
```

That serves exactly what Pages serves — `docs/` at `/`, and nothing above it.

## Tests

```bash
npm test                 # archiver unit tests (node --test archive/)
node docs/tests/run.js   # Puppeteer UI suite over every page
```

`npm test` runs the archiver's `node:test` suites against recorded
fixtures — it never touches the network. The UI suite is **dev-time
only** (not run in CI): it serves `docs/` with `docs/tests/fixtures/data`
substituted for the real `docs/data/`, then drives the pages with
`puppeteer-core`. It needs a local Chrome — the path is set at the top of
`docs/tests/run.js`.

## Running the archiver by hand

```bash
node archive/fetch.js    # hits live LeagueApps, writes docs/data/
```
